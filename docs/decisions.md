# 결정 기록

결정은 추가만 하고 기존 항목은 고치지 않는다. 결정을 바꿀 때는 새 항목을 추가하고, 어떤 항목을 대체하는지 적는다. 다만 2026-09-30 첫 작성일에는 사용자가 검토하기 전에 사실 확인 결과를 반영해 같은 날 초안을 다듬었다 (D-008).

상태는 두 가지로 표시한다.

- 확정: 사용자에게 제시한 계획안에 해당 항목이 들어 있었고, 사용자가 그 계획안을 승인했다. "승인" 줄에 사용자가 무엇을 보고 승인했는지 적는다.
- 잠정: 계획안에 들어 있지 않았거나, 계획안에서 질문으로 남긴 항목에 사용자가 따로 답하지 않았다. 잠정 항목은 [open-questions.md](open-questions.md)에서 다시 확인할 수 있다.

## D-001 지침과 조사 기록을 GitHub 저장소의 md 파일로 관리한다

- 날짜: 2026-09-30
- 상태: 확정
- 내용: 여러 AI 도구가 함께 참고할 수 있도록 지침과 조사 기록을 이 저장소에 md 파일로 둔다. AGENTS.md를 공통 진입점으로 두고, CLAUDE.md는 AGENTS.md를 불러오기만 한다.
- 이유: Codex, Cursor, GitHub Copilot 코딩 에이전트는 AGENTS.md를 읽고, Claude Code는 CLAUDE.md를 읽는다. 원본을 하나로 두면 도구마다 같은 내용을 복사해서 관리할 필요가 없다. git 이력으로 누가 언제 무엇을 바꿨는지 추적할 수 있다.
- 검토한 대안: 작업 지침 md 파일 하나에 모두 담는 방식은 길어질수록 뒷부분 규칙이 덜 지켜지고, 수치와 원칙이 섞인다. Notion은 사람이 읽기에는 편하지만 코딩용 AI 도구가 자동으로 읽지 않는다.
- 제안: Claude Code. 승인: 사용자가 이 항목이 들어 있는 계획안에 "진행해줘"로 답했다 (2026-09-30).

## D-004 저장소를 당분간 공개로 유지한다

- 날짜: 2026-09-30
- 상태: 잠정 (계획안에서 질문으로 남겼고, 사용자가 따로 답하지 않았다)
- 내용: 현재는 원칙과 설계 문서만 있으므로 공개 저장소로 둔다. 개인 매매 정보는 올리지 않는다. 실제 매매 기록이 생기면 비공개 저장소로 분리한다.
- 이유: 공개 저장소는 웹 채팅 AI를 포함한 여러 AI가 인증 없이 읽을 수 있다.
- 위험: 조사 내용이 누구에게나 공개된다. 비밀 값을 실수로 올리면 곧바로 노출된다.
- 제안: Claude Code.

## D-008 첫 작성일의 초안 정정은 원 파일을 고치고, 정정 내역을 새 기록에 남긴다

- 날짜: 2026-09-30
- 상태: 잠정 (계획안에 들어 있지 않았다)
- 내용: 첫 커밋(dc05f77) 이후 같은 날, 사용자가 검토하기 전에 사실 확인에서 발견한 오류를 research/, docs/, AGENTS.md, README.md의 원 파일에서 직접 고치고 GEMINI.md를 추가했다. 지침 성격의 문서(AGENTS.md, research-principles.md, decisions.md)도 이때는 PR을 거치지 않고 고쳤다. 고친 파일과 이유는 [research/2026-09-30-claude-fact-check/](../research/2026-09-30-claude-fact-check/)에 기록했다. 고치기 전 내용은 git 이력에 있다. 이후에는 AGENTS.md의 규칙대로 기존 기록을 고치지 않고, 지침 성격의 문서는 별도 브랜치와 PR로 바꾼다.
- 이유: 틀린 수치와 출처(ETF 유입 기간, 제외 목록)가 담긴 문서를 다른 AI가 먼저 읽으면, 정정 기록을 함께 읽지 않는 한 오류가 퍼진다. 사용자가 아직 검토하지 않은 첫날 초안이므로, 원 파일을 고치고 정정 내역을 남기는 편이 오류가 퍼질 위험이 적다고 판단했다.
- 제안: Claude Code.
