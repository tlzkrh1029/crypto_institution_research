# 결정 기록

결정은 추가만 하고 기존 항목은 고치지 않는다. 결정을 바꿀 때는 새 항목을 추가하고, 어떤 항목을 대체하는지 적는다. 다만 2026-09-30 첫 작성일에는 사용자가 검토하기 전에 사실 확인 결과를 반영해 같은 날 초안을 다듬었다 (D-008).

상태는 두 가지로 표시한다.

- 확정: 사용자에게 제시한 계획안에 해당 항목이 들어 있었고, 사용자가 그 계획안을 승인했다. "승인" 줄에 사용자가 무엇을 보고 승인했는지 적는다.
- 잠정: 계획안에 들어 있지 않았거나, 계획안에서 질문으로 남긴 항목에 사용자가 따로 답하지 않았다. 잠정 항목은 [open-questions.md](open-questions.md)에서 다시 확인할 수 있다.

## D-001 지침과 조사 기록을 GitHub 저장소의 md 파일로 관리한다

- 날짜: 2026-09-30
- 상태: 확정
- 내용: 여러 AI 도구가 함께 참고할 수 있도록 지침과 조사 기록을 이 저장소에 md 파일로 둔다. AGENTS.md를 공통 진입점으로 두고, CLAUDE.md는 AGENTS.md를 불러오기만 한다.

- 검토한 대안: 작업 지침 md 파일 하나에 모두 담는 방식은 길어질수록 뒷부분 규칙이 덜 지켜지고, 수치와 원칙이 섞인다. Notion은 사람이 읽기에는 편하지만 코딩용 AI 도구가 자동으로 읽지 않는다.
- 제안: Claude Code. 승인: 사용자가 이 항목이 들어 있는 계획안에 "진행해줘"로 답했다 (2026-09-30).

## D-012 QNT 가격은 Kraken 공개 API로 구한다

- 날짜: 2026-09-30
- 상태: 확정
- 내용: 업비트와 빗썸에 상장되지 않은 QNT의 시세와 시간봉을 Kraken 공개 API(`/0/public/Ticker`, `/0/public/OHLC`)의 QNT/USD 시장에서 받는다. 가격 반응과 이상 감지의 BTC 비교는 같은 거래소의 BTC/USD 시장으로 한다. 요청은 1.1초 간격으로 보낸다.
- 한계: OHLC 엔드포인트는 최근 720개의 봉만 주므로, 시간봉 기준으로 최근 30일보다 오래된 사건의 QNT 가격 반응은 no_data가 된다. 수집기가 받은 시간봉은 로컬 candles 테이블에 남으므로, 수집기를 계속 실행하면 그 뒤의 기간은 쌓인다.
- 이용 조건: Kraken의 API 안내는 공개 엔드포인트를 개인적으로 이용하는 것을 허용하는 반면, [일반 이용약관](https://www.kraken.com/legal/global-terms) 9항은 Kraken 콘텐츠에 봇, 스크립트 같은 자동화 수단을 쓰는 것과, 서면 동의 없이 Kraken 콘텐츠와 상호작용하는 제3자 프로그램을 만드는 것을 금지한다. 따라서 두 문서가 서로 충돌한다 (2026-09-30 확인). 파생 결과 공개에 대한 조항은 없다 ([2026-09-30 데이터 출처 점검](../research/2026-09-30-claude-data-source-check/README.md)). 파생 결과의 공개는 [open-questions.md](open-questions.md) Q11을 따른다.
- 결정 과정의 누락: Q12의 선택지를 제시할 때 Kraken에 "조건부"라고만 적었고, 두 문서가 충돌한다는 사실은 사용자에게 따로 설명하지 않았다. 이 사실은 결정 뒤인 2026-09-30에 사용자에게 알렸다. 사용자가 이 조건을 보고 결정을 바꾸면 새 항목으로 기록한다.
- 제안: Claude Code (선택지 제시). 결정: 사용자가 "kraken 으로 가자"라고 답했다 (2026-09-30).

## D-013 main에는 PR 병합으로만 반영한다

- 날짜: 2026-09-30
- 상태: 잠정 (계획안에 들어 있지 않았다)
- 내용: AI 도구는 main에 직접 푸시하지 않는다. 지침 문서뿐 아니라 코드, 설정, 조사 기록도 각 도구의 작업 브랜치에서 main을 대상으로 PR을 열고, 사용자가 병합한다.
- 이유: 사용자가 승인한 것은 main 생성과 지침 문서의 PR 절차(D-009)다. AI 도구가 사용자의 허락 없이 다른 브랜치에 푸시하지 않는다는 기존 규칙에 따르면, 그 밖의 변경도 main에 반영하는 방법은 PR뿐이다. 이 방식에서는 사용자가 PR을 병합하기 전까지 main에 새 내용이 보이지 않는다.
- 검토한 대안: 지침 문서가 아닌 변경은 AI 도구가 main에 직접 푸시하도록 허락하는 방식이 있다. 이 방식을 쓰려면 사용자가 도구별로 명시적으로 허락해야 한다.
- 제안: Claude Code.

- 상태: 잠정 (맥북 사양은 사용자가 알려 준 사실이다. FileVault를 켠 채로 운영하는 방식은 Claude Code가 제안했고, 사용자가 아직 답하지 않았다)
- 내용: 사용자가 알려 준 맥북 사양은 Apple Silicon(M1 Pro), 메모리 16GB, macOS Tahoe 26.6.2이고, FileVault가 켜져 있다. 덮개를 열고 전원을 연결한 상태로 계속 둘 수 있다. FileVault는 켠 채로 두고, 재부팅 뒤에는 사용자가 직접 로그인해 수집을 다시 시작한다. 수집이 멈추면 외부 감시 신호(`HEARTBEAT_URL`)로 알아차린다.
- 이유: FileVault를 끄면 자동 로그인을 쓸 수 있지만, 디스크가 암호화되지 않으므로 맥북을 잃어버리거나 도난당하면 `.env`에 둔 봇 토큰과 이메일이 노출될 수 있다. 재부팅은 macOS 업데이트나 전원 문제가 있을 때만 가끔 일어나므로, 그때마다 직접 로그인하는 편이 위험이 적다고 판단했다.
- 이 사양에서 달라지는 점:
  - Apple Silicon 맥북에 macOS Tahoe 26.4 이상이 설치되어 있으므로 충전 한도 기능을 쓸 수 있다 ([collector-spec.md](collector-spec.md) 8절).
  - Apple Silicon 맥북은 꺼진 상태에서 전원이 연결되면 자동으로 켜진다. 그러나 FileVault 잠금 화면에서 멈추므로, 로그인하기 전까지 수집은 시작되지 않는다.
  - 메모리 16GB에서 로컬 AI 모델을 쓸 수 있는지와 그 속도는 [open-questions.md](open-questions.md) Q8을 정할 때 직접 시험한다.
- 거래소 API: 사용자가 설치 장소에서 바이낸스 API(`api.binance.com/api/v3/ping`)를 호출해 HTTP 200을 받았다 (2026-09-30). 설치 장소가 바이낸스 약관상 이용 가능한 지역인지는 확인하지 못했다 ([2026-09-30 프로젝트 피드 점검](../research/2026-09-30-claude-project-feed-check/README.md)).
- 공개 저장소 주의: 사양은 운영 방식을 정하는 데 필요한 수준만 적었다.
- 제안: Claude Code. 사양 확인: 사용자 (2026-09-30).
